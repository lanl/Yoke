class yoke.models.vit.patch_embed.SwinEmbedding(num_vars: int = 5, img_size: (<class 'int'>, <class 'int'>)=(128, 128), patch_size: (<class 'int'>, <class 'int'>)=(16, 16), embed_dim: int = 64, norm_layer: Module | None = None)[source]¶

Bases: Module

SWIN patch embedding.

This SWIN embedding layer takes a channels-first image, applies linear patch embeddings, and rearranges the resulting embedded patches into sequences of tokens.

For an input tensor of shape \((B, C, H, W)\), the embedding uses a convolutional kernel with embedding dimension \(E\) and patch size \(P = (p_h, p_w)\). This operation produces an embedded tensor of shape \((B, E, H', W')\), where:

\[H' = \frac{H}{p_h}, \quad W' = \frac{W}{p_w}\]

The resulting tensor is then rearranged into a sequence of \(H' \times W'\) tokens, each of dimension \(E\), resulting in a final tensor of shape:

\[(B, H' \cdot W', E)\]

Note

The values of \(H\) and \(W\) (i.e., img_size) must be divisible by their corresponding patch size dimensions \(p_h\) and \(p_w\).

Parameters:

  • max_vars (int) – Maximum number of variables

  • img_size (Tuple[int, int]) – Image size (height, width)

  • patch_size (Tuple[int, int]) – Patch size (height, width)

  • embed_dim (int) – Embedding dimension

  • norm_layer (nn.Module, optional) – Normalization layer. Defaults to None.

yoke.models.vit.patch_manipulation module¶

Patch manipulation layers.

Includes merging, expanding, depatching layer definitions.

The goal of these layers is to reduce or increase the number of tokens of a patch embedding while simultaneously modifying the embedding dimension. Hypothetically this should allow a SWIN transformer to learn a heirarchical feature representation for the image.

class yoke.models.vit.patch_manipulation.PatchExpand(emb_size: int = 64, emb_factor: int = 2, patch_grid_size: (<class 'int'>, <class 'int'>)=(64, 64), s1: int = 2, s2: int = 2)[source]¶

Bases: Module

Expand patches and decrease embedding dimension.

This layer receives a tensor of shape \((B, L, C)\), representing batches of \(L\) tokens, each with embedding dimension \(C\). The embedding size \(C\) must match the output of the previous layer.

It is assumed that \(L = H \times W\), where \((H, W)\) define the patch grid from the previous layer.

The expansion process proceeds as follows:

\[(B, H \cdot W, C) \xrightarrow{\text{linear}} (B, H \cdot W, n \cdot C) \xrightarrow{\text{rearrange}} (B, H \cdot s_1 \cdot W \cdot s_2, \frac{n \cdot C}{s_1 \cdot s_2})\]

First, the embedding dimension is expanded linearly by a factor of \(n\). Then, the embedding is rearranged by distributing the added capacity into more tokens, increasing the patch count while reducing the per-token dimension accordingly.

Note

\(n \cdot C\) must be divisible by \(s_1 \cdot s_2\)

Parameters:

  • emb_size (int) – Incoming embedding dimension

  • emb_factor (int) – Up-scaling factor for embedding dimension

  • patch_grid_size (Tuple[int, int]) – Incoming patch-grid dimensions within the token set

  • s1 (int) – Height scaling factor for the patch grid

  • s2 (int) – Width scaling factor for the patch grid

forward(x: Tensor) → Tensor[source]¶

Forward method for patch expansion.

class yoke.models.vit.patch_manipulation.PatchMerge(emb_size: int = 64, emb_factor: int = 2, patch_grid_size: (<class 'int'>, <class 'int'>)=(64, 64), s1: int = 2, s2: int = 2)[source]¶

Bases: Module

Merge patches and increase embedding dimension.

This layer is passed a tensor of shape \((B, L, C)\), i.e., batches of \(L\) tokens, each of embedding size \(C\). The embedding size must match the token embedding dimension from the previous layer. It is assumed \(L = H \times W\) with \(H\) divisible by \(s_1\) and \(W\) divisible by \(s_2\).

The tokens are reshaped into groups of shape:

\[(H', s_1, W', s_2) \text{ with } H' = H / s_1 \text{ and } W' = W / s_2\]

Then, the input is remapped:

\[B \times (H' \cdot s_1 \cdot W' \cdot s_2) \times C \rightarrow B \times (H' \cdot W') \times (s_1 \cdot s_2 \cdot C)\]

Finally, a linear embedding is applied to produce a tensor of shape:

\[(B, H' \cdot W', \text{embedding factor} \cdot C)\]

  • patch_grid_size (Tuple[int, int]) – Incoming patch-grid dimensions within the token set

yoke.models.vit.plain_vit module¶

Plain Vision-Transformer backbone with 2-D RoPE attention.

This module reimplements the regular-grid, plain ViT path of the UMich WAMRViT QuadTreeTransformer in a self-contained, diffusers-free form suitable for use as a swappable backbone within Yoke’s LodeRunner.

The backbone consumes and produces a token tensor of shape (B, N, D), matching the interface of SwinUnetBackbone. It is isotropic: the token count N and embedding dimension D are held constant through all transformer blocks (no patch merging/expansion).

Structural features carried over from the reference architecture:

  • continuous 2-D rotary positional encoding from normalized patch centers,

  • per-head RMSNorm on queries and keys prior to RoPE application,

  • global scaled-dot-product attention over all spatial tokens,

  • parallel attention + SwiGLU-MLP branches from a single pre-LayerNorm,

  • concatenate-then-project (default) or sum fusion of the two branches,

  • one residual update per block,

  • a final non-affine LayerNorm.

class yoke.models.vit.plain_vit.BasicTransformerBlock(num_attention_heads: int, attention_head_dim: int, mlp_ratio: float = 4.0, bias: bool = False, eps: float = 1e-06, concat: bool = True)[source]¶

Bases: Module

Parallel-branch transformer block with SwiGLU MLP and RoPE attention.

Differs from a conventional pre-norm ViT block. From a single non-affine pre-LayerNorm, an attention branch and a SwiGLU-MLP branch run in parallel:

\[\begin{split}z = \text{LN}(x) \\ a = \text{RopeAttention}(z) \\ m = \text{SwiGLU}(\text{Linear}(z)) \\ x \leftarrow x + W_o [a \Vert m]\end{split}\]

where \(\Vert\) is feature concatenation when concat=True (default). When concat=False the branches are each projected to D and summed. There is a single residual update per block.

Parameters:

  • num_attention_heads (int) – Number of attention heads.

  • attention_head_dim (int) – Feature dimension per head. The hidden size is num_attention_heads * attention_head_dim.

  • mlp_ratio (float) – MLP hidden width as a multiple of the hidden size.

  • bias (bool) – Whether attention projections use a bias.

  • eps (float) – Epsilon for LayerNorm and QK RMSNorm.

  • concat (bool) – If True, concatenate-then-project fusion; else sum fusion.

yoke.models.vit.rope module¶

Rotary positional embedding primitives for the plain-ViT backbone.

This module provides self-contained (no diffusers dependency) reimplementations of the transformer primitives used by the UMich WAMRViT plain-ViT path:

  • SwiGLU gated MLP activation.

  • get_1d_rotary_pos_embed() cos/sin generation.

  • apply_rotary_emb() rotary application to queries/keys.

  • RotaryPositionalEmbeddingFromCenters continuous 2-D RoPE built from normalized patch-center coordinates.

  • make_regular_centers() regular-grid patch-center generation.

The conventions here mirror the Hugging Face diffusers implementations (use_real=True with use_real_unbind_dim=-1) so that the resulting architecture matches the reference plain-ViT behavior.

class yoke.models.vit.rope.RotaryPositionalEmbeddingFromCenters(rope_dim_list: list[int], theta: float | list[float] = 10000.0, ntk_factor: float = 1.0, scale: float | list[float] | None = None)[source]¶

Bases: Module

Continuous multi-axis RoPE built from center coordinates.

Generates (cos, sin) rotary tensors for queries/keys from continuous per-token center coordinates. The head dimension is split among the axes according to rope_dim_list (which must sum to head_dim). Each axis coordinate is scaled, passed through get_1d_rotary_pos_embed(), and the per-axis cos/sin segments are concatenated to fill head_dim.

For the regular plain-ViT path there are two axes (x, y) and rope_dim_list = (head_dim // 2, head_dim // 2).

Parameters:

  • rope_dim_list (list[int]) – Per-axis feature dimensions. Must sum to the attention head dimension. Each entry must be even.

  • theta (float | list[float]) – Base period(s) for the frequency progression, either shared across axes or one per axis.

  • ntk_factor (float) – NTK scaling factor.

  • scale (float | list[float] | None) – Per-axis coordinate scaling. A single value broadcasts to all axes; None means unit scaling.

class yoke.models.vit.rope.SwiGLU(dim_in: int, dim_out: int, bias: bool = True)[source]¶

Bases: Module

SwiGLU gated-linear activation.

A gated activation for transformer MLP branches. Given input of dimension \(d_{in}\), an internal linear layer maps to \(2 d_{out}\), which is split into two halves \((a, b)\). The output is:

\[\text{SwiGLU}(x) = a \odot \text{SiLU}(b)\]

where \(\text{SiLU}(z) = z \cdot \sigma(z)\) and \(\odot\) is element-wise multiplication. This matches the diffusers SwiGLU module used by the reference architecture.

Parameters:

  • dim_in (int) – Input feature dimension.

  • dim_out (int) – Output feature dimension.

  • bias (bool) – Whether the internal projection uses a bias. Default True.

yoke.models.vit.rope.apply_rotary_emb(x: Tensor, freqs_cis: tuple[Tensor, Tensor], sequence_dim: int = 1) → Tensor[source]¶

Apply rotary positional embedding to a query or key tensor.

The input x is expected in (B, N, H, D_head) layout (the default sequence_dim=1 indicates the token/sequence axis). Treating consecutive feature pairs \((x_1, x_2)\) as a 2-D point, each pair is rotated by its per-position angle:

\[x_1' = x_1 \cos - x_2 \sin, \quad x_2' = x_1 \sin + x_2 \cos\]

This uses the diffusers use_real_unbind_dim=-1 convention where the rotated-half is formed by interleaving [-x_2, x_1].

Parameters:

  • x (torch.Tensor) – Query/key tensor of shape (B, N, H, D_head).

  • freqs_cis (tuple[torch.Tensor, torch.Tensor]) – (cos, sin) tensors each of shape (N, D_head).

  • sequence_dim (int) – Axis of x corresponding to the sequence/token dimension N. Default 1.

Returns:

Rotated tensor with the same shape as x.

Return type:

torch.Tensor

yoke.models.vit.rope.get_1d_rotary_pos_embed(dim: int, pos: Tensor, theta: float = 10000.0, ntk_factor: float = 1.0) → tuple[Tensor, Tensor][source]¶

Generate 1-D rotary positional embeddings (cos, sin).

Computes rotary frequencies for a set of (possibly continuous) positions. For a feature dimension \(d\) (must be even), \(d/2\) frequencies are computed as:

\[\omega_i = \theta^{-2i/d}, \quad i = 0, 1, \dots, d/2 - 1\]

The phase for position \(p\) is the outer product \(p \cdot \omega_i\). Cosine and sine of this phase are each repeat-interleaved along the feature axis to width \(d\), matching the diffusers convention (use_real=True).

Parameters:

  • dim (int) – Feature dimension of the rotary embedding. Must be even.

  • pos (torch.Tensor) – 1-D tensor of positions, shape (N,).

  • theta (float) – Base period for the geometric frequency progression.

  • ntk_factor (float) – NTK scaling factor applied to theta.

Returns:

(cos, sin) each of shape (N, dim).

Return type:

tuple[torch.Tensor, torch.Tensor]

yoke.models.vit.rope.make_regular_centers(image_size: tuple[int, int], patch_size: tuple[int, int], device: device | str = 'cpu') → Tensor[source]¶

Compute regular-grid patch-center coordinates for a plain ViT.

Centers are normalized to [0, 1] relative to the full image domain. For a patch grid of \(H_p \times W_p\), the center of patch (row, col) is:

\[x = (col + 0.5) \cdot p_w / W, \quad y = (row + 0.5) \cdot p_h / H\]

The returned tensor has columns [x_center, y_center] in row-major (ij) patch order, matching the token order produced by a flattened patch grid.

Parameters:

  • image_size (tuple[int, int]) – Image (H, W) in pixels.

  • patch_size (tuple[int, int]) – Patch (p_h, p_w) in pixels.

  • device (torch.device | str) – Device for the returned tensor.

Returns:

Patch centers of shape (N, 2) with N = H_p * W_p.

Return type:

torch.Tensor
